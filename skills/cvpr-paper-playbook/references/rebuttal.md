# Rebuttal：从问题到可核验回复

针对用户自己的审稿意见和稿件改动。先核实目标年份的页数、时间、新实验及修订限制；用户没给年份时可先写回复内容，不假设可以修改主文或上传任意补充。

## 追踪而不是辩论

保留原意见含义，按 reviewer/comment 编号拆成独立问题。一个长意见可能包含多个请求；同一问题可合并回答但要回链所有原 ID。

| ID | 原问题/忠实摘要 | 对结论的影响 | 回应策略 | 现有证据/所需动作 | 实际完成状态 |
|---|---|---|---|---|---|

回应策略可为：澄清既有证据、补充分析、补实验、纠错、收窄主张、给出科学理由的不同意。先处理影响中心结论的意见。多位审稿人误解同一点时，检查表述是否导致误解。

## 每项回复的结构

1. 直接回应问题，不以感谢段落占据大部分篇幅。
2. 给具体证据：已有表图、实际完成的实验或准确的推导。
3. 写明修改/澄清的位置；没有改就用“拟修改/待完成”，不能写“已补充”。
4. 说明剩余限制或为什么请求超出主张；用科学范围解释，不只说时间不够。

意见错误时先简洁说明理解，再用定义或证据纠正。避免“审稿人没看懂”式语言。合理但做不到的实验要保留未解决状态，并收窄能支持的结论。

## 证据状态

`已有且已定位 / 新增且已完成 / 计划中 / 缺作者输入 / 无法满足并说明原因`

计划中实验不写成过去式。统计、页码、行号、图号、文献、代码链接都必须有真实来源；不确定位置用清晰待填标记并在提交前清除。

## 按篇幅生成两层输出

内部层：完整问题追踪与证据表，不遗漏问题。
对外层：按目标格式和篇幅组织实际回复，可用公共澄清减少重复，保留 ID 便于追踪。

交付：回复策略、可用回复稿、实际改动清单、未解决项。不得把包含待填证据的稿件标记为 ready-to-submit。可以按要求英文回复，并附中文检查要点。
